# X 为你推荐信息流算法

本仓库包含了为 X 平台"为你推荐"信息流提供支持的核心推荐系统。它结合了网络内内容（来自你关注的账号）和网络外内容（通过基于 ML 的检索发现），并使用基于 Grok 的 transformer 模型对所有内容进行排序。

> **注意：** transformer 实现是从 xAI 的 [Grok-1 开源版本](https://github.com/xai-org/grok-1) 移植而来，适用于推荐系统用例。

## 概述

"为你推荐"信息流算法从两个来源检索、排序和过滤帖子：

1. **网络内（Thunder）**：来自你关注的账号的帖子
2. **网络外（Phoenix 检索）**：从全球语料库中发现的帖子

两个来源的内容被组合在一起，并使用 **Phoenix**（一个基于 Grok 的 transformer 模型）进行排序，该模型预测每个帖子的参与概率。最终分数是这些预测参与度的加权组合。

我们已经从系统中消除了所有手工设计的特征和大多数启发式方法。基于 Grok 的 transformer 通过理解你的参与历史（你喜欢、回复、分享等的内容）来完成所有繁重的工作，并使用这些信息来确定哪些内容与你相关。

## 组件

### Home Mixer

**位置：** [`home-mixer/`](home-mixer/)

组装"为你推荐"信息流的编排层。它利用 `CandidatePipeline` 框架，包含以下阶段：

| 阶段 | 描述 |
|-------|-------------|
| 查询水合器 | 获取用户上下文（参与历史、关注列表） |
| 来源 | 从 Thunder 和 Phoenix 检索候选内容 |
| 水合器 | 用额外数据丰富候选内容 |
| 过滤器 | 移除不合格的候选内容 |
| 评分器 | 预测参与度并计算最终分数 |
| 选择器 | 按分数排序并选择前 K 个候选内容 |
| 选择后过滤器 | 最终可见性和去重检查 |
| 副作用 | 缓存请求信息以供将来使用 |

服务器暴露一个 gRPC 端点（`ScoredPostsService`），为给定用户返回排序后的帖子。

---

### Thunder

**位置：** [`thunder/`](thunder/)

一个内存中的帖子存储和实时摄取管道，跟踪所有用户的最近帖子。它：

- 从 Kafka 消费帖子创建/删除事件
- 维护每个用户的原始帖子、回复/转发和视频帖子存储
- 为请求用户提供来自其关注账号的"网络内"帖子候选内容
- 自动修剪超过保留期的帖子

Thunder 无需访问外部数据库即可实现网络内内容的亚毫秒级查找。

---

### Phoenix

**位置：** [`phoenix/`](phoenix/)

具有两个主要功能的 ML 组件：

#### 1. 检索（双塔模型）
找到相关的网络外帖子：
- **用户塔**：将用户特征和参与历史编码为嵌入
- **候选塔**：将所有帖子编码为嵌入
- **相似度搜索**：通过点积相似度检索前 K 个帖子

#### 2. 排序（具有候选隔离的 Transformer）
预测每个候选内容的参与概率：
- 以用户上下文（参与历史）和候选帖子作为输入
- 使用特殊的注意力掩码，使候选内容无法相互关注
- 输出每种操作类型的概率（点赞、回复、转发、点击等）

有关详细的架构文档，请参阅 [`phoenix/README.md`](phoenix/README.md)。

### 候选管道

**位置：** [`candidate-pipeline/`](candidate-pipeline/)

用于构建推荐管道的可重用框架。定义了以下特征：

| 特征 | 目的 |
|-------|---------|
| `Source` | 从数据源获取候选内容 |
| `Hydrator` | 用额外特征丰富候选内容 |
| `Filter` | 移除不应显示的候选内容 |
| `Scorer` | 计算排序分数 |
| `Selector` | 排序并选择前 K 个候选内容 |
| `SideEffect` | 运行异步副作用（缓存、日志记录） |

该框架在可能的情况下并行运行来源和水合器，并具有可配置的错误处理和日志记录。

## 工作原理

### 管道阶段

1. **查询水合**：获取用户最近的参与历史和元数据（例如关注列表）

2. **候选来源**：从以下来源检索候选内容：
   - **Thunder**：来自关注账号的最近帖子（网络内）
   - **Phoenix 检索**：从全局语料库中发现的 ML 帖子（网络外）

3. **候选水合**：用以下内容丰富候选内容：
   - 核心帖子数据（文本、媒体等）
   - 作者信息（用户名、验证状态）
   - 视频持续时间（对于视频帖子）
   - 订阅状态

4. **评分前过滤器**：移除以下帖子：
   - 重复项
   - 太旧的帖子
   - 查看者自己的帖子
   - 来自被屏蔽/静音账号的帖子
   - 包含静音关键词的帖子
   - 以前见过或最近提供的帖子
   - 不合格的订阅内容

5. **评分**：按顺序应用多个评分器：
   - **Phoenix 评分器**：从 Phoenix transformer 模型获取 ML 预测
   - **加权评分器**：将预测合并为最终相关性分数
   - **作者多样性评分器**：衰减重复作者的分数以确保信息流多样性
   - **OON 评分器**：调整网络外内容的分数

6. **选择**：按分数排序并选择前 K 个候选内容

7. **选择后处理**：对要提供的帖子候选内容进行最终验证

---

### 评分和排序

Phoenix 基于 Grok 的 transformer 模型预测多种参与类型的概率：

```
预测：
├── P(favorite)
├── P(reply)
├── P(repost)
├── P(quote)
├── P(click)
├── P(profile_click)
├── P(video_view)
├── P(photo_expand)
├── P(share)
├── P(dwell)
├── P(follow_author)
├── P(not_interested)
├── P(block_author)
├── P(mute_author)
└── P(report)
```

**加权评分器**将这些合并为最终分数：

```
最终分数 = Σ (weight_i × P(action_i))
```

积极行动（喜欢、转发、分享）具有积极权重。消极行动（屏蔽、静音、举报）具有消极权重，压低用户可能不喜欢的内容。

---

### 过滤

过滤器在两个阶段运行：

**评分前过滤器：**
| 过滤器 | 目的 |
|--------|---------|
| `DropDuplicatesFilter` | 移除重复的帖子 ID |
| `CoreDataHydrationFilter` | 移除未能水合核心元数据的帖子 |
| `AgeFilter` | 移除超过阈值的旧帖子 |
| `SelfpostFilter` | 移除用户自己的帖子 |
| `RepostDeduplicationFilter` | 对相同内容的转发进行去重 |
| `IneligibleSubscriptionFilter` | 移除用户无法访问的付费内容 |
| `PreviouslySeenPostsFilter` | 移除用户已经见过的帖子 |
| `PreviouslyServedPostsFilter` | 移除会话中已经提供的帖子 |
| `MutedKeywordFilter` | 移除包含用户静音关键词的帖子 |
| `AuthorSocialgraphFilter` | 移除来自被屏蔽/静音作者的帖子 |

**选择后过滤器：**
| 过滤器 | 目的 |
|--------|---------|
| `VFFilter` | 移除已删除/垃圾/暴力/血腥等帖子 |
| `DedupConversationFilter` | 对同一对话线程的多个分支进行去重 |

## 关键设计决策

### 1. 无手工设计特征
系统完全依赖基于 Grok 的 transformer 从用户参与序列中学习相关性。没有用于内容相关性的手动特征工程。这显著减少了数据管道和服务基础设施的复杂性。

### 2. 排序中的候选隔离
在 transformer 推理期间，候选内容无法相互关注——只能关注用户上下文。这确保了帖子的分数不依赖于批次中的其他帖子，使分数一致且可缓存。

### 3. 基于哈希的嵌入
检索和排序都使用多个哈希函数进行嵌入查找

### 4. 多行动预测
模型不是预测单个"相关性"分数，而是预测许多行动的概率。

### 5. 可组合的管道架构
`candidate-pipeline` crate 提供了一个灵活的框架，用于构建推荐管道，具有：
- 管道执行和监控与业务逻辑分离
- 独立阶段的并行执行和优雅的错误处理
- 易于添加新的来源、水合、过滤器和评分器
