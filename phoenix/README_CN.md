# Phoenix: 推荐系统

本仓库包含 Phoenix 推荐系统的 JAX 示例代码，该系统用于内容排序和检索。Phoenix 对**检索**（从数百万个项目中找到相关候选）和**排序**（通过预测的用户参与度对较小的候选集进行排序）都使用了基于 transformer 的架构。

> **注意：** 本仓库中的示例 transformer 实现是从 xAI 的 [Grok-1 开源版本](https://github.com/xai-org/grok-1) 移植而来。核心 transformer 架构来自 Grok-1，在此处针对推荐系统用例进行了适配，包括自定义输入嵌入和用于候选隔离的注意力掩码。除了特定的扩展优化外，此代码代表了内部使用的模型。

## 概述

Phoenix 是一个预测内容用户参与度（点赞、转发、回复等）的推荐系统。它以两个阶段运行：

1. **检索**：使用近似最近邻（ANN）搜索有效地将数百万个候选缩小到数百个
2. **排序**：使用更具表现力的 transformer 模型对检索到的候选进行评分和排序

### 检索：双塔模型

检索阶段使用**双塔架构**，实现了大规模高效的相似性搜索。

#### 检索工作原理

1. **用户塔**：通过 transformer 编码用户特征和参与历史，生成标准化的用户嵌入 `[B, D]`
2. **候选塔**：为语料库中的所有项目计算标准化嵌入 `[N, D]`
3. **相似性搜索**：使用点积相似性检索前 K 个候选

### 排序：带候选隔离的 Transformer

排序模型使用 transformer 架构，其中**候选在推理期间不能相互关注**。这是一个关键设计选择，确保候选的得分不依赖于批次中的其他候选。

## 关键设计决策

### 1. 基于哈希的嵌入

两个模型都使用多个哈希函数进行嵌入查找

### 2. 共享架构

检索用户塔使用与排序模型相同的 transformer 架构

### 3. 多操作预测

排序模型同时预测多种参与类型：

```
输出: [B, num_candidates, num_actions]
                              │
                              ▼
        ┌─────────────────────────────────────┐
        │ 点赞 │ 转发 │ 回复 │ 点击 │ ... │
        └─────────────────────────────────────┘
```
